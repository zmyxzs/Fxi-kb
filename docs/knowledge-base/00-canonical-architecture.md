# 知识库统一架构与文档总纲

> 本文是知识库全系统的最高权威设计总纲。各专题文档负责展开细节，但不得重新定义与本文冲突的模块边界、数据生命周期、真理源归属或写入权限。

---

## 1. 产品边界与长期定位

这是一个面向个人多项目写作、同人考据与资料整理的**本地优先、纯文本底座、模块化单体知识库**。系统设计以支撑 **3~5 年、数百万字长期创作** 为目标，当前核心目标包括：

- 管理 txt/md 原始资料、原作内容、各项目草稿与写作笔记；
- 保存人物、物品、能力、地点、关系、事件、对话等故事世界对象；
- 用主张、证据、时间线因果、角色认知和动态账本整理原作与项目设定；
- 支持多写作项目（AU、原创、分支版本）强隔离、分歧点（POD）过滤与草稿分支（Draft Forking）；
- 支持通用写作技法、风格档案、范例与创意素材的复用、沙盒试用（Canary）与负向约束（Anti-Pattern）；
- 支持中途平滑引入新系统（三态数值与基线锚点），支持作者合法吃书（Retcon 追溯性修正）；
- 通过支持中文分词的全文检索、可选本地 embedding、POV 视线盲区过滤和场景化剪枝返回精准证据包；
- 为 `novel-Skill` 或外部写作工具提供稳定、可追溯、防 OOC、防视角泄密的只读检索与结构化检查接口。

### 明确不做的事项（非目标）
- 不做重量级 Web/桌面端 UI（优先 CLI、本地 JSON 契约、stdio/HTTP 适配层）；
- 不做 OCR、图片/音视频多模态解析（专注纯文本与 Markdown）；
- 不做全自动整章小说生成或代替作者决定剧情走向；
- 不做多用户并发协作或企业级 RBAC 权限（采用单用户安全写入分级）；
- 不在本地显存（6GB）中强行硬塞大模型微调或同时多开大模型；
- **严禁模型未经审核擅自修改正式知识**。

## 2. 一句话职责划分

```text
真理源（Markdown/TXT）：存储原始文本与经用户确认的核心世界观/项目设定
知识库核心引擎：版本化、关联、流控审核、动态状态计算、POV 视线过滤与检索剪枝
novel-Skill（外部消费者）：理解当前写作任务，调用知识库，组装上下文，生成与检查文本
用户：确认项目设定、处理高危冲突、决定哪些候选内容正式生效、声明合法 Retcon
模型：提供解析、摘要、推测和建议，作为候选提议者（Proposer），不具有事实权威
派生索引（SQLite / FTS5 / Vector）：作为可随时彻底销毁并重建的加速缓存层
```

## 3. 核心设计哲学与长期防坑十诫

### 3.1 纯文本优先与单真理源（Text-First Single Source of Truth）
- **Markdown/TXT 是唯一真理源**：所有核心实体、设定、草稿与素材，底层均以带 YAML Frontmatter 的纯文本持久化；
- **数据库是可丢弃的加速器**：SQLite、FTS5 中文表、向量索引均为衍生数据。任何故障或重构只需运行 `kb rebuild` 即可从纯文本 100% 满血恢复。

### 3.2 审核防疲劳：惰性抽取与分级分流（Lazy Extraction & Triage）
- **按需惰性抽取**：严禁全书无差别深度抽取，仅对作者指定写作区间触发；
- **提议自动分流**：纯事实引用自动标记为可撤销的 `auto_accepted`，高危冲突与 AU 设定阻塞人工审核。

### 3.3 中文检索零暗礁（Chinese FTS5 & Project Lexicon）
- 应用层 jieba 预分词写入 SQLite FTS5 虚拟表，避开 Windows C 编译依赖；
- 实体真名、化名、宗门法宝自动热加载为**项目专有分词词典（`project_lexicon.txt`）**，切词零碎裂。

### 3.4 同人分歧点与蝴蝶效应（Point of Divergence, POD）
- 在同人项目中锚定 `divergence_anchor`；
- 分歧点前 100% 继承原著；分歧点后自动阻断原著**动态情节事件**（如角色死亡），保留**静态世界观法则与地理历史**。

### 3.5 语义场景锚点 vs 物理章节号（Semantic Scene ID）
- 底层**严禁以物理章号（如 Chapter 15）作为主键**；
- 一律采用语义场景 UUID（如 `scene_battle_cliff_01`），章节序号仅作为前端展示标签。插章、重排章节底层数据绝不断链。

### 3.6 中途加装系统：三态数值与历史基线锚点（Three-State & Baseline Anchor）
- 数值属性支持三态：`EXPLICIT`（确知值）、`UNMEASURED`（未统计/混沌态）、`NOT_APPLICABLE`（不适用）；
- 中途引入金币或战力时，插入**基线锚点事件（Baseline Anchor Event）**，向后生效，向前不报错、不回溯。

### 3.7 规则集版本化（Rule Versioning）与合法吃书（Retcon Event）
- 战力与换算规则绑定版本号（`rule_version: v1, v2`），旧章节锁定旧规则，规则更迭不报虚假错误；
- 引入 **Retcon（追溯性修正事件）**，作者主动推翻前设时，系统记录为合法修订，保留历史文本，更新未来真理，绝不误报为逻辑 Bug。

### 3.8 叙述视角盲区过滤（POV Observer Filter）
- 区分客观世界真相与视角认知。检索支持 `pov_character_id`；
- 当处于反派 POV 场景时，系统自动屏蔽主角隐藏底牌，严防写作视角超自然泄密。

### 3.9 文风沙盒试用（Canary）与负向禁写范例（Anti-Pattern）
- 新风格规则进入 `canary` 沙盒，连续高分才转正；
- 建立 `negative_exemplar`（负向范例库），在 Prompt 中显式声明“严禁写成如下生硬腔调”，防止文风恶化。

### 3.10 四级虚拟墓碑软删除（Tombstone Lifecycle）
- 严禁物理 `DELETE`。删除操作一律采用四级语义：`exclude`（排除）、`disable/archive`（停用）、`supersede`（替代）、`purge`（带影响分析的物理清理）；
- 关联关系降级为 `dormant`（休眠），保证旧文可回溯，新检索无污染，永远不发生悬空指针。

### 3.11 知识库统一模型网关与提示词解耦（Model Gateway & Prompt Decoupling）
- **边界清晰**：本项目纯粹为**知识库**，正文写作属于外部项目（如 `novel-Skill`）。知识库内部使用大模型仅限于“导入抽取、OOC审查、风格特征提取、分卷/章节滚动摘要生成与向量化”；
- **全库统一网关（`model-gateway`）**：知识库内部各模块严禁各自重复编写 SDK/HTTP 调用；通过统一网关提供任务分级路由、故障备用切换、结构化容错修复（`json_repair` + Pydantic）、哈希调用缓存与成本记账；
- **提示词模板外部化**：提示词独立存放于 `prompts/` 目录，禁止在业务 Python 代码中硬编码，支持无重启热更新与版本复现；
- **离线模式优雅降级**：断网或 API 故障时，本地 jieba FTS5 搜索、状态账本重算、本地 Qwen3-Embedding 100% 正常运行，大模型任务离线排队，创作者本地查阅绝不卡死。

## 4. 统一概念模型与模块拓扑

```text
storage (纯文本目录底座 + SQLite 衍生加速索引)
  ├── source (原始底本、版本快照、SHA-256 哈希)
  │     └── document (分章、分段、对白定位、chunking, 语义场景 UUID, 分级滚动摘要)
  ├── domain (故事实体、属性、关系、事件、对白结构)
  │     ├── claims (命题四层模型、可信状态、Retcon 追溯修正)
  │     ├── timeline (时空因果 DAG、叙事顺序、区间继承)
  │     ├── character-knowledge (角色认知、POV 视线盲区、防 OOC)
  │     ├── state-ledger (三态数值、基线锚点、变化事件账本与快照)
  │     └── foreshadowing (伏笔生命周期: planted/hinted/resolved/abandoned)
  ├── project (多项目隔离、世界线、分歧点 POD、草稿分支 What-if)
  ├── materials-style (创意素材、金手指、负向禁写范例、风格档案)
  ├── quality-evaluation (风格沙盒 Canary、生成快照、评测回滚)
  ├── analysis-proposals (AI 候选抽取、待审队列、提议分流 Triage)
  ├── lifecycle (exclude / disable / supersede / purge 四级操作引擎)
  ├── index (jieba 中文分词、专有词典热加载、FTS5、向量索引)
  ├── retrieval (作用域过滤、POD 阻断、POV 盲区过滤、场景剪枝)
  ├── model-gateway (统一提供商适配、任务分级路由、结构化修复、哈希缓存、成本记账、提示词注册表)
  └── api-cli (本地 JSON 契约、CLI 适配、错误语义与只读保护)
             │
             └── novel-Skill（外部写作消费者：正文起草、生成与编排在外部项目中完成）
```

## 5. 算力成本、吞吐效率与上下文黄金预算（硬件适配准则）

针对配置（i7-10750H, 40GB RAM, RTX 2060 6GB）：
1. **显存死线（6GB VRAM）**：
   - 本地仅常驻 Qwen3-Embedding-0.6B FP16（占用 ~1.5GB 显存）；
   - 知识抽取与正文生成调用外部轻量极速模型（如 Gemini Flash / DeepSeek V3），速度极快（<1s）、成本极低，严禁在本地显存强行双开大模型导致 CUDA OOM。
2. **写作心流零延迟**：
   - 作者保存草稿时，仅触发纯 CPU 的 **jieba 增量分词与 FTS5 写入（<10ms）**；
   - 向量计算在后台异步闲时队列运行，或由作者手动触发，码字过程绝对不卡顿。
3. **上下文黄金预算（Context Budgeting）**：
   - 场景检索上下文强制收敛在 **2500 ~ 4000 tokens** 黄金甜点区；
   - 依据 `scene_type` 实施场景化剪枝：战斗场景剪除环境修辞，对白场景剪除战力数值；只给大模型 3~5 条硬约束，留足文学发挥空间，彻底解决 Lost-in-the-Middle。
