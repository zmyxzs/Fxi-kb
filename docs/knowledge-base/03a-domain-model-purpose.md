# 故事知识模型：这些区分分别解决什么问题

## 先纠正一个层级问题

“事实、猜测、谎言、身份、时间线”不应被理解为五个平行的资料库分类。它们描述的是同一条故事信息的不同方面。

例如：

> “艾琳其实是王室失踪的公主，她在第 12 章前不知道这件事，并在第 15 章以商人身份对主角说自己只是普通人。”

这句话同时涉及：

- **人物与身份**：艾琳、商人身份、王室公主身份；
- **主张状态**：公主身份可能是原作明确事实，也可能只是当前推测；
- **谎言/误导**：她对主角说“只是普通人”，这是一个发生在具体场景中的话语行为；
- **时间线**：身份何时成立、何时被发现、何时说出这句话；
- **角色认知**：艾琳、主角、读者在每个时间点分别知道什么；
- **证据**：原作哪一章、哪一段支持或反驳这些内容。

因此，知识库的核心不是把资料硬塞进“事实文件夹”或“猜测文件夹”，而是把故事对象、主张、证据、时间和角色认知连接起来。

## 一、故事对象：到底在记录什么

这是知识库的基础层，回答“故事里有哪些东西”。建议至少包括：

| 对象 | 用途 | 典型问题 |
|---|---|---|
| 人物 | 记录人物、别名、身份、性格和状态 | 这个人是谁？有哪些称呼？ |
| 物品/数据 | 记录装备、道具、资源、数值、归属和状态 | 物品什么时候出现？现在谁持有？ |
| 能力 | 记录能力效果、限制、代价、解锁和变化 | 角色此时能不能做到这件事？ |
| 地点/组织 | 记录位置、阵营、规则和从属关系 | 这场事件在哪里发生？谁控制这里？ |
| 关系 | 记录人物之间的关系及其变化 | 两人何时从敌对变成合作？ |
| 事件/场景 | 记录发生了什么、何时发生、参与者和后果 | 这件事先于还是晚于另一件事？ |
| 对话/原文片段 | 保存可引用的原文和说话场景 | 原作是怎样说的？谁在什么情况下说的？ |

这些对象不是“AI 认为的结论”，而是可被多个主张、证据和项目引用的稳定节点。

## 二、主张状态：这条内容应该被怎样相信

任何对象都可能有多个互相冲突的主张。主张应保存内容、来源、适用范围和状态，而不是直接覆盖旧值。

### 1. 原文明确事实

用于记录原著明确写出、设定集明确规定，或用户明确确认的内容。

它解决的是：

- 同人写作时快速查原作依据；
- 防止 AI 把印象、二创或常识当成原著；
- 检查自己的草稿有没有直接违背原作。

“事实”最好写成“有证据支持的主张”，同时保留章节、段落或文件位置。

### 2. 推测/猜测

用于记录根据线索推导出来、但原作没有明确确认的内容。

它解决的是：

- 保存考据思路，不必把猜测伪装成事实；
- 比较多个解释；
- 在新章节出现时重新评估旧推测。

推测应该有依据、置信度、替代解释和当前状态，例如 `open`、`supported`、`weakened`、`rejected`。

### 3. 谎言/错误陈述

谎言不是“整个世界里为假的资料”，而是一个发生在特定时间、由特定角色说出或传播的陈述。它至少要记录：

- 谁说的；
- 对谁说的；
- 说话时角色相信什么；
- 角色想让对方相信什么；
- 这句话对应的命题目前是否为真；
- 读者、其他角色和作者是否已经知道真相。

这样可以区分“角色撒谎”“角色记错”“角色掌握了不完整信息”“作者暂时没有揭示真相”。这对悬疑、身份反转和不可靠叙事尤其重要。

### 4. 身份

身份不是一种独立的真假等级，而是人物与名称、角色、阵营或社会位置之间的关系。身份应支持：

- 真名、化名、称号、伪装身份；
- 身份何时成立或失效；
- 谁知道该身份；
- 身份何时向读者揭示；
- 不同身份是否指向同一个人物；
- 该身份能使用哪些资源、关系和能力。

它解决的是“同一个人被多个名字指代”“人物在不同阶段使用不同身份”“揭示前后称呼和行为不一致”等问题。

### 5. 时间线

时间线也不是一种资料可信度，而是故事对象的时间关系。至少应区分：

- **故事时间**：事件在世界中何时发生；
- **揭示时间**：读者或作者何时得知；
- **角色认知时间**：某个角色何时知道；
- **记录时间**：这条笔记何时被创建或修改。

它解决的是：

- 事件顺序和因果关系错误；
- 年龄、旅程时长、伤势恢复时间不合理；
- 身份在揭示前被错误使用；
- 角色在尚未获知信息前做出不可能的反应；
- 时间回溯、平行世界和 AU 版本混在一起。

## 三、角色认知：专门解决 OOC 和信息泄露

“角色知道什么”不应该只藏在人物简介里，而应作为随时间变化的状态记录。

对于每个角色和每条重要主张，记录：

- `known`：明确知道；
- `suspected`：怀疑但不确定；
- `believed_false`：持有错误认知；
- `unknown`：尚未知道；
- `forgotten` 或 `lost_access`：曾知道但现在无法使用；
- 知道的时间、来源和可信程度。

写作检查时，系统可以问：

1. 这一场景发生时，角色是否已经知道这件事？
2. 如果不知道，他是否有合理线索可以推断？
3. 他使用的能力、物品和称呼在这个时间点是否已经获得？
4. 他的反应是否符合已知关系、性格和当前状态？
5. 草稿是否让角色无来源地说出了作者才知道的信息？

这才是防止 OOC 的主要用途；人物标签本身不能完成这个检查。

## 四、项目和版本：防止三个作品互相污染

三个同时写作的作品必须有独立的 `project_id`。每个项目可以拥有自己的：

- 人物和人物版本；
- 世界线/AU；
- 事件时间线；
- 能力、物品和关系变化；
- 草稿和写作状态；
- 对原作的覆写或偏离。

原作资料可以作为共享只读来源，但项目的改动只能在自己的 overlay 中保存。默认查询只查当前项目；跨项目或共享素材必须显式指定。

这解决的是：同名角色、同名物品、不同 AU 设定、不同作品的时间线和草稿内容被误召回的问题。

## 五、原文和对话：为什么不能只保存抽取后的结论

抽取出的“角色性格谨慎”“两人关系恶化”等条目，不能替代原文。原文片段仍应保留：

- 文件和章节定位；
- 段落或行号范围；
- 场景参与者；
- 说话者、听话者和语境；
- 前后文窗口；
- 原文版本。

它们用于同人写作时查找原作行为、口吻、对白和具体证据，也用于复核 AI 抽取是否错误。结论可以重建，原始文本才是不可替代的依据。

## 六、素材库：用于创作，不冒充原作

金手指、剧情套路、灵感、叙事技巧、优秀片段和写作分析，应放在独立的 `materials` 层。它们可以被项目引用，但默认不能作为原作事实。

素材条目应记录：

- 它是什么创意；
- 适合什么类型或场景；
- 可能的优点、缺点和风险；
- 来自哪里；
- 被哪些项目采用或改写；
- 与哪些人物、能力、事件或主题有关。

这样查询“可用于主角逆袭的能力代价设计”时能找到素材，但不会误把某个素材当成原作角色已经拥有的能力。

## 七、推荐的整体关系

```text
项目 / 世界线 / 版本
        │
        ├── 故事对象：人物、物品、能力、地点、关系、事件、对话
        │       │
        │       ├── 主张：明确事实 / 推测 / 项目设定 / 争议解释
        │       ├── 证据：原文片段、章节、用户确认、AI 分析
        │       ├── 时间：发生时间、有效区间、揭示时间
        │       └── 角色认知：谁在何时知道、相信或误解
        │
        └── 写作草稿：引用对象和主张，但可以产生新的项目设定

素材库 ──显式链接──> 项目或故事对象
原作来源 ──只读引用──> 同人项目
```

## 八、对后续实现的直接影响

数据库或 Markdown 元数据不应只有 `type: fact` 这种字段。至少要能表达：

```yaml
project_id: fanfic-a
subject_id: character:erin
predicate: has_identity
object: identity:lost-princess
claim_kind: canon_fact
truth_status: supported
valid_time: "story: before:chapter-15"
revealed_at: "chapter-15"
known_by:
  - character:erin: unknown
  - character:protagonist: unknown
  - reader: known
evidence:
  - source_id: original-novel
    location: chapter-8/paragraph-12
```

实现时可以先只做文件、SQLite、全文检索和上述元数据；不用一开始就让外部大模型自动解析所有内容。人工补充或修改这些关系是允许的，AI 分析结果必须作为可追溯、可推翻的派生记录保存。

## 一句话总结

这些区分分别服务于不同的写作检查：

- 故事对象回答“有什么”；
- 事实/猜测/谎言回答“这条说法是什么性质”；
- 身份回答“这个人到底是谁、何时以什么身份存在”；
- 时间线回答“什么时候发生、什么时候揭示”；
- 角色认知回答“谁在当时知道什么”；
- 证据回答“凭什么这么判断”；
- 项目隔离回答“这是不是当前作品的设定”；
- 素材库回答“这个创意能否用于写作”。
